Omarchy trata a los agentes de programación con IA como ciudadanos de primera clase, pero no elige un favorito por vos. En cambio, cada CLI importante de agentes viene preparada como un lanzador que se carga en el momento. Los lanzadores son pequeños stubs manejados por mise en ~/.local/bin/, así que no se descarga nada hasta la primera vez que realmente ejecutás uno. Invocá cualquiera de estos y autenticate cuando te lo pida:

Comando Agente
claude Claude Code
codex OpenAI Codex
opencode OpenCode
agy Google Antigravity CLI
copilot GitHub Copilot CLI
crush Crush
grok Grok CLI, de xAI
pi Pi, de Mario Zechner
omp Oh My Pi
ori Ori, el entorno de OpenRouter

ori es el distinto de la lista: corre los otros entornos contra todo el catálogo de modelos de OpenRouter, así que ori claude, ori codex u ori opencode arrancan esos agentes con el modelo que les indiques, y ori code es el agente propio de Ori.

Para envolver otra CLI de la misma manera, ejecutá omarchy-mise-install <package> [command-name]. Los stubs se mantienen al día junto con todo lo demás que maneja mise cuando ejecutás omarchy update (o el alias mup).

El agente predeterminado #

Elegí tu agente predeterminado con omarchy default agent <name> o desde Setup > Defaults > Agent en el menú de Omarchy (Super + Space). Si el agente todavía no está instalado, elegirlo lo instala primero. Un Omarchy recién instalado te va a invitar a hacer esta elección con una notificación por única vez.

Una vez que elegiste, Super + Shift + Ctrl + A abre el agente predeterminado en una ventana de terminal dedicada (o te muestra el selector si todavía no elegiste). También podés lanzarlo directo con una tarea usando omarchy agent prompt "Review this project". Los agentes lanzados así corren sin supervisión, en sus modos de no detenerse a preguntar, ¡así que prepárate para que efectivamente hagan cosas! Y como los agentes se niegan a recordar la confianza sobre tu directorio personal, los lanzamientos desde $HOME arrancan en ~/Work.

También hay atajos de terminal: a corre el agente predeterminado dentro de la terminal actual, mientras que c, cx y cy arrancan OpenCode, Claude Code y Codex directamente (otra vez, en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi y OpenCode siguen el tema de Omarchy cuando lo cambiás.

El panel de agentes #

A la barra superior le aparece un ícono de agentes la primera vez que Omarchy detecta uso de IA para programar en la máquina (y hasta entonces no molesta). El panel detrás de ese ícono sigue todas tus suscripciones en un solo lugar: tu plan, el porcentaje usado de los límites de la sesión de 5 horas y los semanales (o el saldo prepago restante), y el uso de tokens por día y por modelo. Claude Code, Codex y Fireworks están cubiertos de entrada.

Clic izquierdo en el ícono de la barra para abrir el panel, clic derecho para lanzar tu agente predeterminado. Los registros de uso que lo alimentan se regeneran cada 15 minutos con omarchy agent usage-update, y el panel incluso puede combinar el uso de tus otras máquinas a través de una carpeta sincronizada. Mirá el README en $OMARCHY_PATH/shell/plugins/agents/ para ver todas las opciones.

Diagnóstico de fallos #

Omarchy vigila systemd-coredump para detectar fallos de procesos. Cuando algo hace segfault, te llega una notificación de "Process crashed": hacele clic y el fallo pasa a tu agente predeterminado junto con la habilidad diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del volcado de memoria y decidir si vale la pena reportarlo. También podés ejecutarlo a mano contra cualquier PID de coredumpctl list con omarchy agent crash <pid>.

La vigilancia está activada de forma predeterminada. Desactivala desde Trigger > Toggle > Crash Capture (o con omarchy toggle crash-capture) y las notificaciones se detienen; omarchy agent crash <pid> sigue funcionando a mano.

Los fallos también se pueden silenciar programa por programa, que es lo que te ofrece el diagnóstico al final. omarchy crash mute hyprland detiene las notificaciones solo de ese programa, omarchy crash mute hyprland off las vuelve a traer, y omarchy crash mute a secas lista lo que silenciaste. Acepta tanto la ruta del binario como su nombre, así que omarchy crash mute /usr/bin/hyprland hace lo mismo. Poné entre comillas un nombre con espacios, como en omarchy crash mute 'Some App'. Todo lo demás sigue notificando, y el programa silenciado sigue fallando: esto esconde el recordatorio, no arregla nada.

Aplicaciones de escritorio #

El menú Install > AI también trae un par de aplicaciones gráficas de IA: la aplicación de escritorio de ChatGPT y Grok Bot, para chatear con los modelos de xAI.

Modelos locales #

Omarchy recomienda dos formas de correr modelos de lenguaje locales: LM Studio y Ollama. LM Studio ofrece una interfaz gráfica para buscar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran forma de arrancar sin complicaciones. Ollama ofrece una CLI para hacer algo parecido. Pero si sos nuevo en los modelos locales, yo empezaría con LM Studio. Podés instalar cualquiera de los dos desde Install > AI en el menú de Omarchy.

La habilidad de Omarchy #

Las habilidades de agentes ayudan a que la IA use herramientas específicas de una forma específica, y Omarchy incluye una habilidad predeterminada para personalizar el sistema. Por ejemplo, ajustar tu configuración de Hyprland, modificar la barra o incluso crear un tema nuevo desde cero. Está enlazada en los directorios de habilidades de Claude Code (~/.claude/skills), Codex (~/.codex/skills), Pi (~/.pi/agent/skills), Antigravity (~/.gemini/config/skills) y la ubicación genérica ~/.agents/skills, así que la mayoría de los entornos la levantan automáticamente.

Pero conviene tratar esta habilidad como experimental. Distintos modelos la van a aprovechar con distinto resultado. Lo mejor es correr primero en modo de planificación, así tenés una idea de lo que el agente quiere cambiar. Y después estar listo para revertir cambios o incluso invocar omarchy reinstall configs si el agente hace un desastre.
