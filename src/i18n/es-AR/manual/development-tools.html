Editores alternativos #

Omarchy viene con Neovim de forma predeterminada, pero si querés algo un poco más conocido y familiar, podés abrir el menú de Omarchy (Super + Space) y ver las opciones en Install > Editor. Ahí tenemos VSCode, Cursor, Zed, Sublime Text, Helix, Vim y Emacs. Si no encontrás lo que buscás, mirá Install > Package y fijate si no está en algún paquete de Arch (y si no, probá Install > AUR para buscar en el AUR).

Se ofrece coincidencia de temas para VSCode, Cursor, VSCodium y Helix.

Podés definir el editor predeterminado de todo el sistema en Setup > Defaults > Editor.

Entorno #

Omarchy permite configurar un montón de entornos de desarrollo desde la sección Install > Development del menú de Omarchy (Super + Space). Por supuesto vas a encontrar Ruby on Rails, pero también los tres grandes entornos de ejecución de JavaScript (Node.js, Bun, Deno), además de frameworks populares de PHP como Laravel y Symfony. Ah, y también están Go, Rust, Python, Java, Elixir (con Phoenix), .NET, OCaml, Zig, Clojure y Scala. ¡Es una selección amplísima!

La mayoría de estos entornos los maneja Mise. Es una herramienta que te deja instalar y correr varias versiones de un lenguaje de programación en la misma máquina. Es como rbenv o rvm para Ruby, o virtualenv para Python, pero funciona para un montón de entornos distintos.

Para instalar Ruby, por ejemplo, ejecutarías mise use -g ruby, que instala Ruby y además lo deja como predeterminado global. O, si tu proyecto tiene un archivo .ruby-version, te alcanza con ejecutar mise i en la raíz de ese proyecto.

Docker #

Docker casi no necesita presentación. Te permite correr contenedores aislados, y Omarchy instala todo lo necesario para que ande bien, incluidos Docker mismo y Docker Compose.

De forma predeterminada, tu usuario no está en el grupo docker. Ese grupo es, en la práctica, root sin contraseña: cualquier cosa que esté ahí puede hacer docker run -v /:/host y tomar control de la máquina, así que un solo script o dependencia maliciosa corriendo con tu usuario estaría a un comando de ser root. Por eso, en la línea de comandos usás Docker con sudo (sudo docker ps, sudo docker compose up), y las herramientas gráficas que hablan con el demonio, o sea la TUI de Docker en Super + Shift + D y la máquina virtual de Windows, piden autorización cuando la necesitan. Si querés recuperar la comodidad de trabajar sin el grupo y entendés el riesgo, activalo desde Setup > Security > Sudoless Docker (o ejecutá omarchy-setup-security-sudoless-docker), que te agrega al grupo docker después de una advertencia; a partir de ahí, docker a secas y el alias d vuelven a funcionar sin sudo.

Acordate de probar el comando Lazydocker para manejar tus contenedores en una TUI muy linda con Super + Shift + D; la primera vez pide autorización, salvo que hayas activado Docker sin sudo.

Podés configurar las bases de datos más comunes para desarrollo local en Docker desde Install > Development > Docker DB en el menú de Omarchy.

CLI de GitHub #

La CLI de GitHub te permite autenticarte con tu cuenta de GitHub y clonar repositorios privados desde ahí. Está enganchada como uno de los stubs de mise que se cargan en el momento, así que la primera vez que ejecutás gh se instala solo. Para autenticarte, ejecutá gh auth login. Después podés clonar repositorios privados con gh repo clone org/repo.

También podés hacer un montón de otras operaciones de GitHub con este comando. Ejecutá gh para ver todo lo que se puede.

También hay un stub que se instala al vuelo para ghui, que sirve para manejar tus pull requests en una TUI. Y lazygit viene preinstalado, si también querés manejar git desde una TUI.
