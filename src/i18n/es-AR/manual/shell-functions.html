Omarchy viene con un conjunto de funciones de shell para simplificar tareas comunes y encapsular llamadas con parámetros enrevesados.

Compresión #

  • compress [file/dir]: Crea un archivo tar.gz a partir del archivo o directorio.
  • decompress [file.tar.gz]: Descomprime un archivo tar.gz.

Discos #

  • iso2sd [image.iso]: Crea un disco de arranque en una tarjeta SD con la iso indicada, eligiendo la unidad de forma interactiva.
  • format-drive [device] [name]: Formatea un disco entero con una sola partición exFAT (que también funciona en Windows y macOS). Ejecutalo sin argumentos para ver los discos disponibles. ¡Cuidado con esto!

Disposiciones de desarrollo #

Disposiciones de desarrollo con varios paneles, al instante, para tmux:

  • tdl [ai]: Crea un Tmux Dev Layout con tu editor, un agente de IA y una terminal. Usá los alias de los agentes, como tdl c para opencode o tdl cx para Claude Code, o pasá un segundo agente para correr los dos, como tdl c cx.
  • tds: Crea un Tmux Dev Square con editor, seguimiento de diferencias (con hunk diff --watch), terminal y opencode.
  • tdlm [ai]: Crea una ventana tdl para cada subdirectorio del directorio actual.
  • tsl [count] [command]: Crea un enjambre de paneles en grilla, todos corriendo el mismo comando (ideal para agentes de IA).

Las mismas disposiciones están disponibles para Herdr como hdl, hds, hdlm y hsl.

Worktrees de Git #

  • ga [branch]: Crea un worktree y una rama nuevos al lado del repositorio actual y te mete adentro.
  • gd: Elimina el worktree actual y su rama (te pide confirmación antes).

Observadores de rsync #

  • rsw [source] [destination]: Arranca un observador en segundo plano que sincroniza con rsync el origen hacia el destino cada vez que algo cambia. El destino puede ser una máquina remota, como rsw ~/Work/app nyc-dev:Work/app.
  • lsw: Lista todos los observadores activos.
  • dsw: Detiene todos los observadores activos.

Reenvío de puertos por SSH #

Ideal para hacer desarrollo web con los privilegios de contexto seguro de localhost contra una máquina remota.

  • fip: Reenvía uno o más puertos de una máquina remota a localhost por SSH.
  • dip: Desconecta uno o más puertos reenviados.
  • lip: Lista todos los reenvíos de puertos SSH activos.

Supongamos que levantás un servidor de desarrollo en el puerto 3000 de una máquina a la que llegás como nyc-dev. Entonces podés ejecutar fip nyc-dev 3000 para reenviar ese puerto, y así localhost:3000 llega en realidad a nyc-dev:3000, pero sin necesidad de certificados SSL para establecer el contexto seguro que hace falta para probar web sockets y cosas por el estilo.

Reconexión por SSH #

ssh está envuelto en una función que limpia la terminal si una conexión se corta mientras un tmux, un Herdr o un editor remoto la tenían tomada, y después se reconecta automáticamente cuando se cae una sesión interactiva (Ctrl-C corta el ciclo de reintentos).
