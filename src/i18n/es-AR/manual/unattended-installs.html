La ISO de Omarchy puede instalarse sin nadie frente al teclado. Si el instalador encuentra un segundo disco etiquetado cidata con sus archivos de configuración, los copia, se saltea por completo el asistente de instalación y reinicia solo en el sistema terminado. Sin una ISO especial, sin una entrada extra en el menú de arranque: si no hay un disco así conectado, no cambia nada y tenés el asistente normal.

Esto hace que Omarchy sea excelente como imagen base para entornos de desarrollo desechables: creás una máquina virtual en Proxmox o con Packer, la arrancás, te vas, y entrás por SSH. cidata es la etiqueta NoCloud de cloud-init, así que todas las herramientas de virtualización comunes ya saben cómo conectar un disco así.

Los archivos de configuración #

Los archivos son exactamente los que escribe el asistente del instalador, así que la forma más fácil de conseguir un juego inicial es hacer una instalación interactiva (en una máquina virtual, por ejemplo) y copiar lo que escribió en /root:

Archivo Obligatorio Para qué sirve
user_configuration.json Sí Disco, nombre de host, zona horaria, teclado
user_credentials.json Sí Nombre de usuario y hash de la contraseña
user_full_name.txt No Nombre completo para git
user_email_address.txt No Correo para git
user_encrypt_installation.txt No true cuando la configuración lleva un bloque disk_encryption definido
authorized_keys No Claves públicas SSH, una por línea
tailscale_authkey No Clave de autenticación de Tailscale para unirse a tu tailnet en el primer arranque

Generá el hash de la contraseña para user_credentials.json con openssl passwd -6 "yourpassword".

También podés dejar un archivo vacío llamado defer-provisioning en lugar de user_credentials.json. Eso ejecuta la misma instalación de preparación para otro dueño que podés activar de forma interactiva: la máquina se instala sin datos personales, y quien la arranque primero elige su teclado y crea su usuario. Ese es el modo para armar imágenes en serie, donde el disco no debería llevar las credenciales de nadie.

Acceso por SSH #

Cuando está presente authorized_keys, la instalación deja las claves como el ~/.ssh/authorized_keys del usuario, habilita sshd y le abre el firewall. (Una instalación estándar de Omarchy trae openssh con el servicio desactivado y el puerto cerrado, así que una máquina desatendida quedaría inalcanzable de otra forma). La instalación solo agrega tus claves: no relaja ninguna otra opción de autenticación del demonio SSH.

Cuando está presente tailscale_authkey, la máquina se une a tu tailnet en el primer arranque: Tailscale se instala desde los paquetes incluidos en la ISO, el firewall permite la interfaz de la tailnet, y una tarea en segundo plano hace la unión en cuanto la máquina realmente tiene red, reintentando hasta lograrlo. Usá una clave reutilizable y preautorizada para que una misma imagen de disco sirva para muchas máquinas.

Armar el disco cidata #

Cualquier sistema de archivos con la etiqueta correcta funciona. Una ISO chiquita es la forma más fácil: 

mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/

Después conectala a la máquina virtual junto con la ISO de Omarchy. Acá va un ejemplo completo con Proxmox: 

qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101

El orden de arranque pone el disco primero a propósito: en el primer arranque el disco vacío pasa de largo hacia la ISO, y de ahí en adelante el sistema instalado arranca del disco.

Dos advertencias #

Las instalaciones desatendidas con cifrado no son del todo desatendidas: alguien igual tiene que escribir la frase de acceso de LUKS en el primer arranque. Y el bloque disk_encryption de user_configuration.json lleva esa frase en texto plano, así que tratá un disco cidata armado a partir de una instalación cifrada como el secreto que es.
