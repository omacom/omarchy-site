El escritorio de Omarchy corre como un único proceso de Quickshell de larga vida llamado omarchy-shell, y casi todo lo que ves en pantalla es un plugin adentro de ese proceso. La barra es un plugin. También lo son los paneles que bajan de ella, las superposiciones a pantalla completa como el selector de emojis y el gestor del portapapeles, el propio menú de Omarchy, la pantalla de bloqueo, el diálogo de polkit y los servicios sin interfaz que vigilan tu batería y entibian la pantalla de noche.

Eso no es solo un detalle de implementación. Significa que podés apagar partes del escritorio, reemplazarlas o escribir las tuyas sin tocar una línea del código fuente de Omarchy.

Los plugins propios vienen con Omarchy y viven en $OMARCHY_PATH/shell/plugins/. Todo lo que agregues vos, sean tus propios experimentos o algo que encontraste en GitHub, vive en ~/.config/omarchy/plugins/. Los dos se descubren de la misma forma al arrancar; la única diferencia es dónde están en el disco.

Ver qué tenés # 

omarchy plugin list

Eso imprime todos los plugins descubiertos con su id, si están activados, si son propios o de terceros, sus tipos y su nombre visible. Agregá --json si se lo vas a pasar a otra cosa.

Los ids de los plugins usan espacios de nombres. Los incorporados arrancan todos con omarchy. (omarchy.clock, omarchy.network, omarchy.notifications) y ese espacio de nombres está reservado, así que un plugin de terceros nunca puede reclamarlo.

Activarlos y desactivarlos # 

omarchy plugin enable omarchy.tailscale
omarchy plugin disable omarchy.weather

O usá el menú: Setup > Plugins tiene Enable, Disable, Add, Clone y Remove, cada uno con un selector que solo ofrece los plugins que tienen sentido para esa acción.

El estado de activación se guarda en ~/.config/omarchy/shell.json, y la regla cambia un poco según el tipo de plugin. Un plugin de terceros está activado exactamente cuando su id aparece en algún lugar de ese archivo: como entrada en la disposición de la barra, como entrada en plugins[] o como bar.id. Los plugins propios que no son widgets de la barra funcionan al revés: están activados de forma predeterminada y solo se apagan si los listás en disabledPlugins[].

Un plugin de barra completa no tiene estado apagado. Siempre hay exactamente una barra, así que la reemplazás activando otra. La ubicación de los widgets de la barra está explicada en la barra superior.

Agregar un plugin desde git #

Un plugin de terceros es simplemente un repositorio git con un manifest.json en su raíz. 

omarchy plugin add https://github.com/acme/omarchy-weather.git --enable

Antes de hacer nada, te avisa claramente que los plugins corren como código arbitrario y sin aislamiento dentro de tu proceso de shell de larga vida, te muestra la URL y te pide confirmación. Tomate eso en serio. Un plugin no es un archivo de configuración: es código que corre todo el tiempo que dure tu sesión, con acceso a todo lo que alcanza tu cuenta de usuario. Agregá solo repositorios que estés dispuesto a ejecutar, y leelos antes de activarlos.

Después clona el repositorio en un directorio de preparación, valida el manifiesto, rechaza la instalación si otro plugin ya reclama ese id, y lo mueve a ~/.config/omarchy/plugins/<id>/. Sin --enable te pregunta si lo querés activar ahora, y podés decir que no e ir a leer el código primero. Nunca ejecuta nada del plugin, nunca ejecuta un enganche de instalación y nunca pide sudo: clona archivos, revisa el manifiesto y cambia un bit por IPC.

Actualizar es un pull de avance rápido sobre esa misma copia:

omarchy plugin update acme.weather
omarchy plugin update

Sin un id, actualiza todos los plugins manejados por git que tengas. Te muestra las diferencias antes de aplicarlas, se niega a actualizar si tenés cambios locales que no puede saltear con un avance rápido, y revierte si la nueva revisión no pasa la validación. 

omarchy plugin remove acme.weather

Quitarlo primero lo desactiva, y después lo borra si es una copia de git (el repositorio sigue estando arriba) o lo desenlaza si es un enlace simbólico. Una carpeta de plugin hecha a mano y sin repositorio git se mueve a una copia de respaldo con fecha dentro del directorio de plugins, en lugar de borrarse directamente.

Clonar un plugin incorporado para modificarlo #

Esta es mi parte favorita. Si querés cambiar cómo se comporta un widget incorporado, no edites los archivos que están en $OMARCHY_PATH: le pertenecen al paquete y la próxima actualización los va a sobrescribir. Clonalo en su lugar: 

omarchy plugin clone omarchy.clock

Eso copia el plugin entero a ~/.config/omarchy/plugins/dhh.clock (con tu nombre de usuario, no el mío), le cambia el nombre a "My Clock", lo activa y hace que el shell pase del incorporado a tu copia, conservando la posición y las opciones del widget de barra que ya tenías. Agregá --edit para abrir enseguida el directorio nuevo en tu $EDITOR, que es lo que hace por vos Setup > Plugins > Clone Plugin desde el menú.

El prefijo con tu nombre de usuario hace que el id de tu clon sea tuyo, así compartirlo no choca con el de nadie más. Las llamadas al id incorporado original se enrutan a tu clon, así que nada de lo que apuntaba a omarchy.clock necesita cambios. Y si haces un lío, omarchy plugin remove dhh.clock vuelve a poner el incorporado.

Guardar un archivo en cualquier lugar debajo de ~/.config/omarchy/plugins/ recarga el código del plugin automáticamente, así que podés dejar el editor abierto y ver cómo caen tus cambios.

Escribir el tuyo #

Un plugin es un directorio con un manifest.json y algo de QML. El manifiesto declara schemaVersion: 1, un id, un name, una version, uno o más kinds, y un objeto entryPoints que apunta al archivo QML de cada tipo:

Tipo Qué es
bar-widget Un componente que la barra activa puede colocar en una sección
panel Una ventana flotante persistente o invocada
overlay Una superposición a pantalla completa
menu Una superficie de menú invocada
service Un singleton sin interfaz
bar Una barra completa que reemplaza la incorporada

Un plugin puede declarar varios tipos a la vez: el plugin de medios es a la vez service y bar-widget. Los widgets de barra reciben un bloque extra barWidget con un nombre visible, una categoría, un defaultSection opcional y allowMultiple, que indica si tiene sentido tener más de uno en la barra. La mayoría de los widgets lo ponen en false; los separadores y los indicadores lo ponen en true.

Antes de publicar nada, revisalo:

omarchy plugin validate ./my-plugin

Eso corre las mismas verificaciones que hace el shell al cargar: la versión del esquema, los campos obligatorios, un id que no esté reservado, puntos de entrada que sean rutas relativas seguras y que existan de verdad, un punto de entrada por cada tipo que declaraste, y ningún enlace simbólico en ninguna parte de la carpeta.

Para el panorama completo, el código es la documentación: shell/README.md en el repositorio de Omarchy cubre el esquema del manifiesto, el contrato de IPC del shell y la forma exacta de shell.json, y shell/plugins/README.md lista todos los plugins propios con su id, sus tipos y sus puntos de entrada.

Compartir el tuyo con el mundo #

Una vez que hiciste algo que te gusta, ponelo en un repositorio git público. Ese es todo el mecanismo de distribución: cualquiera puede después ejecutar omarchy plugin add contra tu URL y tenerlo funcionando en segundos.

Para que la gente lo encuentre de verdad, publicalo en omarchyplugins.com. Ese es el directorio comunitario de plugins del shell de Omarchy, y es el primer lugar donde mirar cuando te preguntás si alguien ya construyó el widget que estás por escribir. ¡Recorrelo antes de empezar!
